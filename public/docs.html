API de precios GasGas estable · en producción desde 2017

Precios de combustible de las 14,194 estaciones de México — promedio, mínimo, máximo y desviación estándar por nivel geográfico, con serie histórica diaria. Fuente: Comisión Nacional de Energía, con validación y limpieza de atípicos.

https://api.gasgas.com.mx/api

Para tu equipo: especificación OpenAPI 3.1 (contrato formal de la API, compatible con Swagger UI y generación de clientes) · colección de Postman con todos los endpoints listos para importar.

Inicio rápido

Tu primera llamada en 60 segundos. Elige tu lenguaje:

curl "https://api.gasgas.com.mx/api/precios?market=estado&value=Jalisco&days=1&product=regular"
import requests

r = requests.get("https://api.gasgas.com.mx/api/precios",
                 params={"market": "estado", "value": "Jalisco",
                         "days": 1, "product": "regular"})
print(r.json())
const r = await fetch(
  "https://api.gasgas.com.mx/api/precios?market=estado&value=Jalisco&days=1&product=regular"
);
console.log(await r.json());
Respuesta:

  "regular": "23.9295",  "premium": "29.0847",  "diesel": "27.0410",
  "min": "22.9900",  "max": "24.4900",  "std": "0.2968",
  "stations_count": 333,
  "updated_at": "2026-07-20T12:00:46.227Z"
}

Autenticación

Los endpoints de esta referencia son de consulta abierta con fines de evaluación — los mismos que alimentan gasgas.com.mx.

Los contratos comerciales operan con una API key por cliente enviada en el encabezado x-api-key, con límites de uso definidos en tu contrato y, si tu caso lo requiere, endpoints dedicados (así operan nuestros clientes en producción). La llave se entrega en el setup y es rotable a solicitud.

curl -H "x-api-key: TU_LLAVE" "https://api.gasgas.com.mx/api/precios?..."

Convenciones

  • Números como texto. Los precios llegan como strings con 4 decimales ("23.9295") para no perder precisión. Conviértelos a decimal en tu sistema; para mostrar, redondea a 2.
  • updated_at en cada respuesta. Timestamp UTC (ISO 8601) del último cálculo. La base se actualiza con 2 cortes al día (6 AM y 2 PM, hora de México) a partir de la publicación de la CNE — verificable en updated_at.
  • Fechas de negocio en hora de México. El corte days=1 corresponde al último día con datos publicados (zona America/Mexico_City), no al día UTC.
  • Niveles geográficos. nacional · estado · municipio (llave compuesta Estado|Municipio, la barra se codifica %7C) · código postal y estación individual disponibles por contrato.
  • Nombres insensibles a mayúsculas. value=jalisco y value=Jalisco son equivalentes.
  • Validación de datos. Los promedios excluyen precios fuera de rangos plausibles (limpieza de atípicos documentada). stations_count declara la base muestral de cada cifra.

Precios agregados

GET/api/precios

Promedio, mínimo, máximo y desviación estándar de un mercado en un periodo.

ParámetroValoresDescripción
market requeridonacional · estado · municipioNivel geográfico.
value requeridoall · Jalisco · Jalisco%7CZapopanall para nacional; nombre del estado; o Estado|Municipio.
days requerido1 · 7 · 30Hoy, últimos 7 o últimos 30 días.
product opcionalregular · premium · dieselA qué combustible corresponden min/max/std. Default: regular.
Ejemplo — Zapopan, hoy:
curl "https://api.gasgas.com.mx/api/precios?market=municipio&value=Jalisco%7CZapopan&days=1&product=regular"
CampoTipoDescripción
regular · premium · dieselstringPrecio promedio por litro del periodo (4 decimales).
min · max · stdstringMínimo, máximo y desviación estándar del producto solicitado.
stations_countintEstaciones que respaldan la cifra (base muestral).
updated_atstringÚltimo cálculo (ISO 8601, UTC).

Errores

Los errores llegan en JSON con el código HTTP correspondiente: {"error": "descripción"}

CódigoSignificadoQué hacer
400Falta un parámetro o tiene formato inválido.Revisa los parámetros requeridos del endpoint.
401Llave ausente o inválida (endpoints con contrato).Verifica el encabezado x-api-key.
404El mercado solicitado no existe.Valida el nombre contra /estados o /municipios.
429Límite de uso excedido.Espera y reintenta con backoff. Los límites están en tu contrato; nunca bloqueamos en silencio.
5xxError de nuestro lado.Reintenta con backoff exponencial. Nuestro monitoreo lo detecta en ≤1 hora y el equipo es alertado.
Ejemplos de cuerpo de error (formato garantizado; el texto puede variar):
// 400 — parámetro faltante o inválido
{ "error": "Falta el parámetro estado" }

// 404 — ruta o mercado inexistente
{ "error": "Not Found" }

// 429 — límite de uso excedido (endpoints con contrato)
{ "error": "Límite de uso excedido" }

// 500 — error interno (el equipo es alertado)
{ "error": "Error obteniendo precios" }

Caché

  • Los GET responden con Cache-Control: public, max-age=300, s-maxage=300 — la respuesta puede servirse desde el borde (CDN) o tu navegador hasta 5 minutos.
  • Como la base se actualiza con 2 cortes al día, esos 5 minutos no afectan la frescura práctica del dato. La fuente de verdad de la antigüedad es siempre updated_at, no la hora de la respuesta.
  • Recomendación: si tu sistema consulta con alta frecuencia, cachea de tu lado por mercado y refresca tras los cortes (6 AM y 2 PM, hora de México).
  • Las peticiones que no son GET responden Cache-Control: no-store.

Seguridad y datos

  • TLS obligatorio. Toda la API se sirve sobre HTTPS; las peticiones HTTP se redirigen.
  • Llaves por cliente. Los contratos operan con API key propia (encabezado x-api-key), rotable a solicitud sin costo. Nunca compartas tu llave en código del lado del cliente (navegador o apps móviles); llámanos desde tu backend.
  • Sin datos personales. La API sirve exclusivamente datos públicos agregados de precios de combustible — no maneja PII, por lo que integrarte no agrega superficie de riesgo de privacidad a tu sistema.
  • Retención. El histórico se conserva de forma continua desde mayo 2024; los agregados publicados no se reescriben tras su corte.

Versionado y estabilidad

  • El esquema de respuesta es estable: los campos existentes no cambian de nombre ni de tipo sin nueva versión.
  • Agregar campos nuevos no se considera cambio incompatible — programa tu parser para ignorar campos desconocidos.
  • Un cambio incompatible se publica como versión nueva con 90 días de aviso a los clientes con contrato, y se anota en el changelog.
